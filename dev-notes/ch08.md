# Ch08 开发留痕：即插即用工具系统

> 按阶段追记，每段记四样：用户关键原话 / 关键产出 / 用户拒绝或纠偏 / 翻车与返工。

## 阶段 1：Brainstorm 定稿（2026-10-12）

**用户关键原话**：

- 「我要用 Superpowers 模式把客服系统的工具层从几个写死的内置工具,升级成即插即用的工具系统。」
- 七项功能：统一工具表（内置启动登记、MCP 现问现拿）、JSON Schema 校验失败回灌、只读/写权限且写操作只有 `create_ticket` 并等前端确认、统一执行引擎（暂时性故障才重试、写操作不自动重试、三类错误、结果挑字段并枚举翻成人话）、`tool_audit_logs` 无外键且审计失败不拦执行、物流与售后两个 MCP Server 且内置 `query_logistics` 下线、建工单 `interrupt` 预览确认流（投诉按钮那条路不动）。
- 技术选型定死：MCP 官方 Python SDK + Streamable HTTP；`langchain-mcp-adapters` 的 `MultiServerMCPClient`。
- 工单预览卡片前端用 Vibe Coding，不套 brainstorm、TDD、code review。提示词类任务用标注样例代替 TDD。
- 假数据：「A」（确定性种子，不按字面每次随机）。
- 接入形态：「1」（每轮刷新工具表，薄外壳进执行引擎，保留 `create_react_agent`）。
- 逐节「继续」通过架构、工具契约、执行引擎、测试策略。
- 审计表：「审计表按照这个来」，并贴出完整 `tool_audit_logs` DDL。

**关键产出**：

- `docs/plans/2026-10-12-ch08-tools-design.md`
- 拍板：确定性假数据；方案 1；权限按我们配置的 Server 只读继承，写操作只有 `create_ticket`；`interrupt` 在建工单外壳，引擎只认确认标记；审计表以用户 DDL 为准（`tool_source` + `mcp_server` 分列，中文状态枚举，无外键）

**用户拒绝或纠偏**：

- 设计稿里的审计表（单列 `source`、`error`、`result_summary VARCHAR(512)`、复合索引）作废，改用用户 DDL：`tool_source ENUM('builtin','mcp')`、`mcp_server`、`error_message`、`result_summary TEXT`、`retry_count TINYINT`、`duration_ms` 可空，以及三把单列索引。

**翻车与返工**：无代码返工。本会话未接通 Context7 MCP，设计文档约定实现前再核对 SDK 与 `interrupt` 接口，对不上就停。
