## 阶段 5：T13 真实上游验收 + System Prompt 根因修复（2026-09-30）

**用户关键原话**：「我刚才改好了API的Key，你检测一下是否有问题，没有问题就进行下一步」（上游 DeepSeek / deepseek-chat）。

**关键产出**：
- 验收脚本两处适配：`tee /dev/tty` 非交互 shell 不可用 → 改为先落变量再回显
- **验收 2 首跑翻车**（第二轮答「不知道您要退哪件商品」）→ systematic-debugging 四步排查：
  1. 根因调查：直连实验确认历史消息**确实在** prompt 里，模型却不用
  2. 变量分离：langchain 路径 / 原生 SDK / 无 system 三对照全部命中 → 排除序列化与历史丢失
  3. 假设验证：同案例带原版 System Prompt 重跑 3 次挂 2 次（temp=0 仍复现）→ **根因=System Prompt 第 2 条「不编造/查不到」被模型泛化到对话记忆**，凡似订单查询的问题宁可拒绝也不引用上下文
  4. 根因修复：约束改写为「对话历史里用户说过的信息直接引用作答，不属于编造」与「仅系统实时数据查不到时才说查不到」两条分开 → 修复后 4/4 命中
- 完整验收重跑（真实 DeepSeek）：**三条标准全部通过**（SSE 逐 token 流式 / 第二轮命中「还没拆封的空气炸锅」/ 抽取三字段全对），pytest 41 全绿

**用户拒绝或纠偏**：无。

**翻车与返工**：即上——验收 2 失败暴露的 Prompt 缺陷，是本章最有价值的教训：**约束类 System Prompt 措辞不当会抑制上下文利用**，靠多轮对照实验定位，已把「直接引用/查不到」双关键词写进防回退测试。
