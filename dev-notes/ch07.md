## 阶段 11：ch07.1 退货政策失效——用户拍板「办理与否走代码硬规则」

**用户关键原话**：「退货退款政策失效了」+（我提出让意图模型带 action 布尔后）「不要交给模型猜，直接硬编码进规则里，规则是死的，只要话术里有『我要退款』『这个能退吗』不就是要办理退款吗」。

**诊断**：ch06 路由把 退款退货/售后 一律送 refund_prep——「退货政策是什么」这类**通用规则咨询**也被订单选择器拦截，政策答案没了（我第一轮设计确实把咨询句卷进了办理流，用户实测抓出）。

**方案（按用户拍板改走代码规则，撤销模型 action 方案）**：
- 我第一版实现走了「意图四件套加 action 布尔让模型判」，被用户纠偏推翻；最终 graph.py 落 `wants_refund_process(raw_query)` 硬规则：办理词表（我要/帮我/给我/我想/申请/办理/退掉/退了吧/赶紧/立刻/马上）或点名 1001-1005 → 进子流程；否则「退款退货/售后」走知识检索。消解槽位非空（追问具体订单，ch06 问句直通语义）也算办理
- IntentSchema 回退两字段（intent/confidence），四件套 JSON 形态不变；action 通道由意图节点写、逐轮重置
- 真机双向验证：「退货政策是什么」→ 186 token 知识流+引用、无选择器；「我要退款」→ action=True 弹选择器
- 测试：规则词表 6 断言 + 路由 2 回归（政策句不进子流程/办理句仍进）；ch06 六用例触发句「这个能退吗」→「我要退款」（新语义下自洽，并留注释说明无办理词的指代句走知识）
