# Ch02 开发留痕：Function Calling 工具链（查数据 + 工单落库）

> 按阶段追记，每段记四样：用户关键原话 / 关键产出 / 用户拒绝或纠偏 / 翻车与返工。

## 阶段 0：需求与环境（2026-10-05）

**用户关键原话**：
- 「我要用 Superpowers 模式给现有的客服系统装上查数据的能力，用 Function Calling 让模型自己决定调什么工具——工具链要长在客服聊天本身，用户在聊天页问一句就能触发。」
- 要点：①FastAPI+SQLAlchemy 分层骨架，Docker 起 MySQL；四表 faq/conversations/messages/tickets 灌测试数据 ②LangChain @tool 定义五工具：query_order/query_product/query_logistics 内部随机造数（不接真接口），query_faq 用 SQL LIKE，create_ticket 写 tickets ③工具基础设施：注册管理/Schema 校验/错误处理/超时重试/结果回灌 ④接现有 SSE 聊天页：模型定工具→执行→回灌收敛，工具执行推状态帧，聊天记录落库，气泡显示工具徽章 ⑤只做单轮调用，不做 Agent Loop/向量 RAG
- 环境拍板：本机无 Docker，装「colima」（纯 CLI，免 GUI 授权）

**关键产出**：任务跟踪（#15-18）；colima+docker 安装启动后台进行中

**用户拒绝或纠偏**：无。

**翻车与返工**：环境侦察发现本机无任何 Docker 运行时（Docker Desktop/OrbStack/colima/podman 均缺）→ 经用户拍板装 colima。

## 阶段 3：TDD 构建 T1-T3（2026-10-05）

**用户关键原话**：执行方式沿用 ch01「主会话顺序 + 阶段评审」，计划评审通过后开工。

**关键产出**：
- T1 Docker MySQL（colima + docker-compose，mysql:8.0，业务库 ecom_cs + 测试库 ecom_cs_test，用户 DDL 四表 + 6 条 faq 种子）
- T2 async engine（aiomysql）+ Settings 增 MYSQL_*/TOOL_* 配置
- T3 四表 ORM 严格对齐用户 DDL + truncate 夹具

**用户拒绝或纠偏**：无。

**翻车与返工**（5 起，均当场修复）：
1. `docker compose` 插件缺（brew docker 公式只含客户端）→ 改用独立 `docker-compose`
2. Docker Hub 直连被拒 → 三个镜像源（daocloud/1ms/dockerproxy）拉取后重打标 `mysql:8.0`
3. SQLAlchemy 装到 2.1.3：`BIGINT(unsigned=True)` 构造参数被移除 → 改普通 `BigInteger`（ORM 只映射不建表，无影响）
4. pytest-asyncio 每测试新事件循环，模块级 engine 连接池跨循环复用报 "Future attached to a different loop" → 夹具改为每测试建 engine + teardown dispose
5. **init 脚本 mysql 客户端默认 latin1，DDL 枚举值与种子中文全乱码**（ORM 插入'进行中'报 Data truncated）→ 三脚本加 `--default-character-set=utf8mb4` 并删卷重建
6. truncate 被外键拦 → 夹具里 SET FOREIGN_KEY_CHECKS=0/1 包裹；测试两处笔误（漏 await flush、Ticket 缺 ticket_no）

**用户关键原话**：（构建期无新增指令，按定稿计划推进。）

**关键产出**：

- T8 SSE 端点改造（user_id 必填、整型会话 id、依赖阶段 404、orchestrator 事件帧化）+ 内存 store 退役
- T9 工具选型 eval 样例集 9 条（含 2 条预期 null），真实模型双轮 9/9 稳定
- T10 聊天页（工具徽章 running/done、localStorage user_id 与整型 conversation_id、新会话按钮）+ acceptance 第 4 节
- 单测 53 全绿；真机验收：SSE/上下文续接/抽取全过，物流问题触发 query_logistics 按返回作答

**用户拒绝或纠偏**：无。

**翻车与返工**（6 起）：
1. SSE 端点又写成 return Response 协程（ch01 同款坑第二次踩）→ 改回异步生成器直出，坑已写入两章 dev-notes
2. `uv add` 连带升级 pydantic/fastapi：`AsyncIterable[ServerSentEvent]` 返回注解不再被容忍 → 显式 `response_model=None`
3. 测试夹具只换了 orchestrator 的 session_factory，依赖层还连业务库 → 依赖与编排器统一注入测试库工厂
4. LangChain 消息 type（human/ai）与 DB 枚举（user/assistant）不一致 → MessagesRepo 显式映射
5. **编排器最初漏拼 SYSTEM_PROMPT**（直接喂 DB 历史，客服角色丢失）→ 每轮由编排器拼接不落库，测试钉死
6. create_ticket 选型不稳（deepseek 倾向先追问/先查订单）→ 工具描述强化「立即调用不追问」+ 样例改为带问题描述的纯建单请求 → 3/3 稳定；「邮费是多少」直问会被理解成订单运费、模型反问订单号不调工具——**换个说法**（运费规则/邮费政策）即触发 query_faq 查空并诚实回答，验收 3 达成
