# Ch02 开发留痕：Function Calling 工具链（查数据 + 工单落库）

> 按阶段追记，每段记四样：用户关键原话 / 关键产出 / 用户拒绝或纠偏 / 翻车与返工。

## 阶段 0：需求与环境（2026-10-05）

**用户关键原话**：
- 「我要用 Superpowers 模式给现有的客服系统装上查数据的能力，用 Function Calling 让模型自己决定调什么工具——工具链要长在客服聊天本身，用户在聊天页问一句就能触发。」
- 要点：①FastAPI+SQLAlchemy 分层骨架，Docker 起 MySQL；四表 faq/conversations/messages/tickets 灌测试数据 ②LangChain @tool 定义五工具：query_order/query_product/query_logistics 内部随机造数（不接真接口），query_faq 用 SQL LIKE，create_ticket 写 tickets ③工具基础设施：注册管理/Schema 校验/错误处理/超时重试/结果回灌 ④接现有 SSE 聊天页：模型定工具→执行→回灌收敛，工具执行推状态帧，聊天记录落库，气泡显示工具徽章 ⑤只做单轮调用，不做 Agent Loop/向量 RAG
- 环境拍板：本机无 Docker，装「colima」（纯 CLI，免 GUI 授权）

**关键产出**：任务跟踪（#15-18）；colima+docker 安装启动后台进行中

**用户拒绝或纠偏**：无。

**翻车与返工**：环境侦察发现本机无任何 Docker 运行时（Docker Desktop/OrbStack/colima/podman 均缺）→ 经用户拍板装 colima。

## 阶段 1：Brainstorm（2026-10-05）

**用户关键原话**：
- 三问三答：存储「DB 为唯一真源（内存 SessionStore 退役）」；用户标识「前端 localStorage 匿名 id」；编排路线「bind_tools + 手写单轮编排」
- 设计稿初版被纠偏：「有修改意见」→ 用户直接给出**四张表完整 DDL**（BIGINT 自增会话主键、中文 ENUM 状态、可读工单号 T+日期+序号、外键、updated_at）并明确「表的设计按照这个」

**关键产出**：
- `docs/plans/2026-10-05-ch02-tools-design.md`：用户 DDL 原文采纳为唯一表结构规范 + 4 条适配点（conversation_id 改整型 / 工单号生成规则 / messages 无 name 列的工具名反查 / 中文 ENUM 的 SQLAlchemy 映射）
- colima + docker engine 安装启动完成（后台任务）

**用户拒绝或纠偏**：初版表设计（uuid 主键、英文枚举、自增工单号）被用户 DDL 替换——用户对数据建模有明确主张，其余设计（DB 真源/编排/SSE/测试策略）未提异议。

**翻车与返工**：无。
