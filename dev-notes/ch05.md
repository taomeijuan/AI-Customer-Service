## 阶段 5：评审修复 + 知识路径误拒根因定位（2026-10-08）

**用户关键原话**：「工具调用和引用的问题没有被解决」。

**关键产出**：
- agent_node.py 修复：ToolMessage→evidence 提取块被重复粘贴两份（citations 每条工具结果进两次、编号错乱），删除重复块
- test_eval_routing 对齐 ch05 架构：query_faq 工具已被 RAG 检索路径取代，样例移除该绑定；投诉样例移除（投诉走意图分类→comfort，不到工具选择层）
- **知识路径误拒根因**：curl 真机抓包发现「退货政策是什么」回 FALLBACK_TEXT、citations 空。逐层定位：语料 41 条健全 → 检索命中正确（top1 即标准答案）→ rerank 分数 0.32 < 阈值 0.45 被闸拒
- **标定错误溯源**：0.45 是 ch03 的 COSINE 相似度阈值；ch04 设计文档（rag2-design.md）把同一个值原样照搬给 bge-reranker-v2-m3 的 relevance_score——两把尺子不可混用，且当时 .env 尚未配置 RERANK_API_KEY（reranker 为 None 时闸退化为「有空证据即放行」），错误被遮盖
- 实测标定（对照组 + 6 条真实问句）：无关≈0.00 / 弱相关 0.19–0.23 / 正确相关 0.25–0.35 / 明显相关≥0.45 → 阈值改 0.25（config 添加标定注释）
- 新增边界回归测试：rerank 0.26 放行 / 0.23 拒答
- 端到端验证：订单1002 → tool×2 + [1][2] + citations 2 条；退货政策 → 52 delta + [1][4] + citations 10 条

**用户拒绝或纠偏**：拒绝用 grep 触碰 .env 与 .env.example（含密钥的文件一律不读），改为经 pydantic-settings 读单个非敏感数值确认。

**翻车与返工**：本轮最大教训——**配置常量跨语义迁移时必须重新标定，不能照搬数值**。0.45 从 COSINE 尺度搬到 relevance 尺度时没人质疑，因为 rerank 功能当时未被真实启用验证；ch05 换上真实 key 后闸大面积误拒，知识路径整体瘫痪。教训二：伪流式摘除后 live 链路验证要以 curl 抓 SSE 帧为准，前端报障先逐事件核对后端帧。

## 阶段 7：工具假数据确定性化——「同一个问题答案不一样」真相（2026-10-08）

**用户关键原话**：「为什么同一个问题是不同的答案，你是编出来的吗」。

**关键产出**：
- 追根：不是模型编的。ch02 工具有意用 random.choice/uniform 模拟实时数据，每调随机吐（状态/商品/金额/承运商/轨迹全随机），模型忠实转述 → 答案自然前后不同。实锤：连调 3 次同订单号，3 套完全不同数据
- 用户选定方案：确定性假数据（不接真库、同类随机问题一并解决）
- 实现：md5(order_no/商品名+salt) 派生随机种子（进程间稳定，不用 Python 内置 hash——其带随机盐）；时间改种子派生固定锚点（原 datetime.now() 会随调用时刻漂移）
- query_order/query_logistics/query_product 三工具全部确定性化；新测试 4 个（同实体全等断言/8 订单号多样性），全量 165 绿

**用户拒绝或纠偏**：无明显纠偏；通过 AskUserQuestion 拍板「确定性假数据」而非接 MySQL。

**翻车与返工**：无代码翻车。认知收获：**「数据源随机 + 模型诚实」会被用户误读为「模型编造」**——模型忠实转述反而让假数据的不一致暴露得更彻底。教学系统里假数据也要自洽，否则信任崩盘。

## 阶段 8：真·流式输出恢复——逐字可见 + 前导话术防御（2026-10-09）

**用户关键原话**：「检测一下流式输出，前端看不出来流式输出，会影响用户的体验」。

**关键产出**：
- 诊断：ch05 切图时「伪流式」——ReAct 跑完才把 final_text 切 3 字快发（113 帧 50ms 内吐完），前端只见打字机一闪
- 修复一：astream 加 version="v2"（统一 {type,ns,data} 字典格式），处理 messages 流块，langgraph_node=="agent" 过滤，token 实时冒为 delta。实测：113 token 均匀流 9 秒 / 二次验证 6.3 秒
- 修复二（类层级陷阱）：langchain-core 1.6.6 起类层级翻转——AIMessageChunk 是 AIMessage 的子类，isinstance(tok, AIMessageChunk) 对所有真实 token 恒 False，v1 时代过滤写法把流全杀（debug 探针 + __mro__ 实证后才能定位）
- 修复三：工具帧改 AsyncCallbackHandler 实时推（running/done），chips 在回答流出前就位（此前 post-hoc 补推 → 先答案后 chips）
- 修复四：前导话术防御——模型给工具申请附带正文（如英文 "I'll check your order..."），黑盒提取时天然剥掉但真流式会泄出。双保险：系统提示词禁止申请附带文字 + 流层 12-token 看门缓冲（工具信号一到即弃缓冲；agent 节点完成/流结束冲刷余量）
- 验证：流拼接与落库答案逐字一致（157=157）；工具帧 11:12:11.8 先于首 delta 11:12:12.3；9 测试全过、全量 166 绿

**用户拒绝或纠偏**：无。

**翻车与返工**（2 起）：
1. **依赖版本陷阱**：langchain-core 1.6 消息类层级翻转，旧文档/旧代码的 isinstance(AIMessageChunk) 写法全部静默失效——不报错、只过滤，这类 bug 只能靠逐帧 debug 输出打中。Context7 文档只写 v2 格式不写类层级
2. 3 字切片兜底让「拼起来一致」的测试全部假绿——测流式必须断言**帧数与时刻形态**（粒度/顺序/时间跨度），不能只比对最终文本
