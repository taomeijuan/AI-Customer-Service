# Ch04 设计文档：混合检索 + 重排 + 生成质控 + 评估体系

> 状态：已定稿（2026-10-06，用户批准）
> 范围：不做指代消解、多轮改写；满意度反馈纯前端采集（ch09 数据飞轮入口）
> 流程：Superpowers（brainstorm → 计划 → TDD 构建 → 评审 → finish）

## 1. 需求与验收

需求：
1. 混合检索：关键词路落在 Milvus 2.5 原生 BM25（text 挂 BM25 函数、chinese analyzer），dense+BM25 各 Top-50，hybrid_search 配 RRF 融合
2. 重排：bge-reranker-v2-m3 精排 Top-10；组装 prompt 最相关放首尾
3. 元数据过滤：按品类等字段先过滤再检索
4. Query 理解：口语改写归一；同义词只在检索侧扩展
5. 生成质控：引用编号映射章节路径可跳原文；检索不到/置信度低显式拒答；自评不够拒答并入低置信度池；System Prompt 列负面知识
6. 评估体系：难度梯度评估集 + Recall@K/MRR/Faithfulness + 四策略对比分桶报告
7. 前端：引用编号可点看原文；👍/👎 一次性锁定反馈（纯前端）

验收标准：
1. 四策略对比报告能跑出数字
2. 问带具体型号的问题，BM25 路能命中
3. 答案引用编号能定位回原文，聊天页可点开
4. 问知识库没有的内容，明确拒答且问题进低置信度池

## 3. 数据模型（用户 DDL 原文，规范来源）

```sql
-- ch04 · RAG 进阶 · 建表 DDL
-- 本章新建:low_confidence_questions(低置信度问题池)、faith_cases(编造个案台账)
-- 生成阶段模型自评知识不够答就拒答,把原话落进这张池子,是 ch09 数据飞轮的入口
-- 本章只靠 useful 自评判入池(useful=false 才入,不单独存该字段);ch09 会给这张表 ALTER 加归并字段

SET NAMES utf8mb4;

CREATE TABLE low_confidence_questions (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  conversation_id BIGINT UNSIGNED NULL                    COMMENT '来源会话',
  raw_question    TEXT            NOT NULL                COMMENT '用户原话,带情绪口语',
  source          ENUM('retrieval_low_conf','self_check','user_feedback') NOT NULL COMMENT '入池入口:检索证据低 / 生成自评不足 / 用户反馈未解决',
  reason          TEXT            NULL                    COMMENT '判不能的原因,留作复盘',
  created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '入池时间',
  PRIMARY KEY (id),
  KEY idx_source (source),
  KEY idx_created_at (created_at),
  CONSTRAINT fk_lcq_conversation FOREIGN KEY (conversation_id) REFERENCES conversations (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='低置信度问题池';

CREATE TABLE faith_cases (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
  eval_id       VARCHAR(16)     NOT NULL                COMMENT '评估集题号,如 A43;一题一行',
  bucket        VARCHAR(24)     NOT NULL                COMMENT '题目所属桶:A_policy / B_model / C_colloquial / E_multi',
  query         VARCHAR(512)    NOT NULL                COMMENT '用户问题原文',
  strategy      VARCHAR(24)     NOT NULL DEFAULT 'hybrid_rerank' COMMENT '产出这条答案的检索策略',
  answer        TEXT            NOT NULL                COMMENT '被判编造的那版生成答案原文',
  reason        TEXT            NOT NULL                COMMENT '裁判给的理由:编在哪一句',
  citations     JSON            NULL                    COMMENT '这一轮喂给模型的 Top-K 证据全集快照:[{n,chunk_id,section_path,question,answer}];答案里的角标 [n] 就是这份列表的序号,答案通常只引用其中两三条;老数据没记为 NULL',
  judge_model   VARCHAR(64)     NULL                    COMMENT '判这条的裁判模型',
  status        ENUM('未解决','已解决','无需解决') NOT NULL DEFAULT '未解决' COMMENT '处置状态,人工点按钮改',
  seen_count    INT UNSIGNED    NOT NULL DEFAULT 1      COMMENT '被判编造的累计次数(跨轮)',
  first_seen_at DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '第一次被判编造的时间',
  last_seen_at  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '最近一次被判编造的时间',
  resolution    VARCHAR(300)    NULL                    COMMENT '处置说明:标已解决要写清怎么解决的,标无需解决要写清为什么不用改;退回未解决时清空。空着的处置在台账上等于没有交代',
  resolved_at   DATETIME        NULL                    COMMENT '最近一次被标为已解决/无需解决的时间;复发后仍保留,用来标「复发」',
  PRIMARY KEY (id),
  UNIQUE KEY uk_eval_id (eval_id),
  KEY idx_status (status),
  KEY idx_last_seen_at (last_seen_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='ch04 忠实度编造个案台账';
```

适配点：两表 DDL 经 `db/init/05-ch04.sql`（IF NOT EXISTS）+ `scripts/init_ch04.sh` 手动入两库；conftest truncate 列表补两表。

## 5. 检索流程

```
query
 → query_rewriter（LLM：{normalized, synonyms[]}，只扩展检索词）
 → 检索文本 = normalized + " " + synonyms 拼接
 → Milvus hybrid_search：
     dense AnnSearchRequest(bge-m3 向量, Top-50)
   + sparse AnnSearchRequest(BM25, 检索文本, Top-50)
   + RRFRanker(k=60) → 融合候选
 → 元数据过滤：category 前缀（可选参数）
 → bge-reranker-v2-m3 精排 → Top-10 证据 [{chunk_id, section_path, questions, answer, score}]
```

三策略退化形态：dense-only / bm25-only / hybrid(无 rerank) —— 供评估对比与降级。

## 6. 生成质控

- **证据组装**：rerank 后 Top-10 按 `[1..K]` 编号；**最相关一条放首位、次相关放末位**，中间按序（首尾注意力）；每条含 section_path（供引用映射）
- **生成**：build_structured_model 复用（function_calling）→ `{useful: bool, reason: str, answer: str}`；useful=true → answer 带 `[n]` 角标；useful=false → answer 为拒答话术，且写 low_confidence_questions(source='self_check', reason)
- **检索低置信**：Milvus 融合后 top1 分数 < RETRIEVAL_LOW_CONF_THRESHOLD → 不生成直接拒答（source='retrieval_low_conf'）
- **负面知识清单**（System Prompt 追加）：不承诺具体到账时间与时效数字；不承诺任何未写明的价格、优惠、库存；不替物流公司承诺送达时间；不承诺赔偿金额与方式；不知道就引用检索结果或拒答
- **citations**：SSE done 帧 data 带 `citations: [{n, chunk_id, section_path, question, answer}]`（本轮 Top-K 证据全集）

## 7. 评估体系

- 评估集字段：`{id, bucket, query, ground_truth_points[], relevant_chunk_ids[]}`；负例 `expected_refusal: true` 不计检索指标、只验证拒答与入池
- 检索段：`recall_at_k(relevant, ranked_ids, k)`、`mrr(relevant, ranked_ids)` 纯函数
- 生成段：Faithfulness judge（deepseek-chat）——输入 question + citations 全集 + answer，判「答案是否完全被证据支持」；编造 → faith_cases 台账（uk_eval_id 一题一行：seen_count++、last_seen_at 更新、已解决→复发退回未解决、citations 快照、judge_model 记录）
- runner：逐题跑指定策略 → 检索指标按桶聚合 + 生成段 Faithfulness 抽查 → Markdown 报告（对比表）落 docs/evals/ch04-report-{date}.md
- 策略矩阵：dense / bm25 / hybrid / hybrid_rerank 全跑
